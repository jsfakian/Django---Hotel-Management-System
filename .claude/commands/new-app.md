Scaffold a new Django app for the HMS project. Usage: /new-app <app_name> [description]

This command generates all the boilerplate for a new Django app following HMS conventions:

1. Create the app: `docker compose exec django python manage.py startapp <app_name>` (from HMS/ directory)
2. Generate the following files with HMS-standard content:
   - `<app_name>/models.py` — base model with `created_at`, `updated_at` timestamps
   - `<app_name>/serializers.py` — ModelSerializer skeleton
   - `<app_name>/views.py` — ModelViewSet skeleton with JWT permission_classes
   - `<app_name>/urls.py` — DefaultRouter registration
   - `<app_name>/admin.py` — @admin.register skeleton
   - `<app_name>/tests.py` — pytest test class skeleton with factory-boy
   - `<app_name>/apps.py` — AppConfig (already generated by startapp)
3. Remind the user to:
   - Add the app to `INSTALLED_APPS` in `HMS/HMS/settings.py`
   - Register the router in `HMS/HMS/api_urls.py`
   - Run `make makemigrations` then `make migrate`

Follow all conventions from CLAUDE.md: related_name on ForeignKey, DecimalField for money, explicit permission_classes, select_related in get_queryset.
